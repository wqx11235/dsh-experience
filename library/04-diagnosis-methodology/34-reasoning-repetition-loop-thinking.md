# 模型陷入推理重复循环：整轮只思考、不调用工具，界面一直转圈却显示「已完成」

> 一个带推理档的模型在长会话里把「规划下一步」写成了无穷递归的自我催促（「做。」「好。」「（执行）」），
> 一次思考涨到 9.8 万字符、1.4 万次「做。」，整轮**一个工具调用都没有**；
> 但宿主看到的是正常的 `step/end` + `turn/end completed`，于是不报错、不超时、不中断——用户以为卡死。

## 症状

- 连续多轮回复**只有思考**，内容是反复的「做。」「好。」「（执行）」「（现在）」，几百到上万次，没有任何工具调用。
- 界面一直转圈；用户催「在跑吗，怎么又卡了」「怎么有 2 个插话中，卡在这」，最后只吐出一段没有动作的文本。
- 后端状态看着完全正常：`step/end` 正常、`turn/end` 的 `reason.kind` 是 `completed`（不是 error / aborted）；
  `sessionStats.pendingCalls` 为空、`openStep: null`。**从宿主视角它根本没在跑。**
- 思考长度异常暴涨：正常几百字符 → 2 万 / 2 万 / 2.4 万 / **9.78 万**字符，其中「做。」出现 14,652 次。
- 一次实测的逐轮曲线（同一会话）：

| 轮次 | 思考字符 | 「做。」次数 | 工具调用 | 结束状态 |
|---|---|---|---|---|
| 冲突轮 step 1 | 15,721 | 1,448 | 1 | 继续 |
| 冲突轮 step 6 | **97,805** | **14,652** | **0** | 用户手动中断 |
| 次轮 | 21,254 | 3,097 | 0 | completed |
| 再次轮 | 19,995 | 2,848 | 0 | completed |
| 再次轮 | 23,984 | 2,661 | 0 | completed |

- 怎么量：会话落盘是 `session.v4.jsonl.zstd`（每个会话一个目录，内含该文件）。解压后逐行 JSON，
  统计 `assistant/message` 里 `type:"reasoning"` 的 `.length` 与 `/做。/g` 计数，按 turn 列出来即可。

```js
// 解压后的 session.v4.jsonl，逐行前先 split('\n')
const ev = lines.filter(Boolean).map(l => { try { return JSON.parse(l) } catch { return null } }).filter(Boolean);
for (const e of ev) {
  if (e.type !== 'assistant/message') continue;
  const c = (e.data.message && e.data.message.content) || [];
  const r = c.filter(b => b.type === 'reasoning').map(b => b.text || '').join('');
  const tools = c.filter(b => b.type === 'tool_use' || b.type === 'tool-call').length;
  console.log(e.data.turn, e.data.step, r.length, (r.match(/做。/g) || []).length, tools);
}
```

判据：**思考长度 > 10,000 且「做。」> 500、工具调用 = 0** 即可确认。

## 原因

### 引发链（复盘到事件级）

爆发前是**连续四轮「打磨格式」型任务**：改答卷排版 → 写作业代码 → 写讲解稿 → 「把讲解稿转成图片发我」。
这类任务的共同点是**完成标准模糊**（几页？多大？附录要不要？），只能靠模型自己审查，
于是「检查」被搬进了思考里，变成只动脑不动手的推演。

四个具体卡点，按时间：

1. **起点不是最后那一轮**。转折轮第一步在动手写文件**之前**就已经思考了 15,721 字符、1,448 个「做。」，
   内容是反复权衡「手写还是转格式、4 页还是 5 页、要不要附录」。
2. **真正的引爆点是「反斜杠转义」**。它要改一行含 `\section*{...}` 的 LaTeX，在 PowerShell 的 `-replace`
   正则转义和改用脚本之间反复推演，越推越乱，整段滑进「做。做。做。」，最后 97,805 字符。
3. **自我催促是被历史奖励过的**。同一会话早前的几轮里，「做。」出现 1 次 / 27 次 / 77 次，
   而那些轮**任务都成功交付了**。等于持续告诉模型「多想 + 自己催自己是有效的」——没有负反馈，所以停不下来。
4. **用户喊停根本没进去**。用户插话「你在干什么，思考中全是做做做」被记成一条 `next-step` 注入，
   紧接着同位置的注入带 `"outcome":"canceled"` —— 因为上一步的响应已经在生成中，这条插话被取消，
   没进到下一步，模型照跑 9.8 万字符。**这就是「我喊了停它还在转」的机制原因。**

### 正反馈（关键）

这些思考全文留在会话历史里，每轮随 prompt 重发（一次实测：消息面 338,729 token，其中助手侧输出约 92% 是这类思考）。
模型看到自己上一轮的循环样板，下一轮继续模仿 → 越滚越大 → 上下文越脏 → 更容易退化。**污染是自我维持的，不会自愈。**

### 无兜底

宿主对 reasoning 没有重复检测、没有长度上限；模型只要输出了思考，该步就算有产出，
直接 `step/end` → `turn/end completed`。于是**不会报错、不会超时、不会中断**，只是「什么都没干就结束了」。

### 放大因素

长上下文（数十万 token）+ 高推理档位（reasoning effort = high）+ 多细节自检型任务，三者叠加时概率显著上升。

### 常见误区

看到 `turn/end completed` + `pendingCalls{}` + `openStep:null` 就判「没在跑 / 已正常结束」——
技术上没错，但用户体验就是卡死。**「后端空闲」≠「用户看到正常」。**

## 避坑（可复制）

### 识别（10 秒判据）

- 回复只有思考、没有工具调用，且思考里出现**连续两句以上**「做。/好。/（执行）」→ 已进入循环。
- 不要「再想一步就好」，那一步本身就是循环。

### 逃生（模型侧）

- 发现自己在思考里重复同一个词/句 → **立刻停止思考，直接发工具调用**。想清楚一句就落地，不在思考里「预演执行」。
- 写文件 / 跑命令这类确定性动作：先 glob 一次确认编号，然后 write，不要「再核对一遍」。

### 止血（会话侧）

- 一旦出现**两轮以上**纯思考循环，这条会话的上下文已经埋了数万字符的样板，**别在原会话继续催**
  （催一句就再循环一轮，还会把垃圾再翻一倍）。重新开会话最快。
- 要救原会话：先退出宿主（会话文件是 append-only，且宿主内存持有状态），再解压
  `<会话目录>/session.v4.jsonl.zstd`，丢掉 `assistant/message` 里所有 `type:"reasoning"` 块后重新压缩。
  **务必先备份**；不改结构（只清 reasoning 文本）比删整条消息安全。
- 想打断正在生成的响应，**按中断**，别靠发消息——发消息要等当前步结束才可能注入，而它可能永远不会结束。

### 兜底（配置 / 模型）

- 长会话（>20 万 token）把推理档位从 high 降档，或换不那么「爱自检」的模型跑重活。
- 该失效模式目前多数宿主**没有自动检测**，靠人 / agent 自己认。

### 别再犯

- 别用「再想想」解决「想太多」。循环的解法是**立刻动手**，不是想得更清楚。
- 别把 `turn/end completed` 当成「任务成功」。要看这一轮有没有工具调用产出。
